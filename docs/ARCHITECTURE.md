## Curriculum contract

Items use stable IDs such as `hangul-314f`, `word-namu`, and `phrase-hello`. Lesson IDs are `u1-l1`, etc.; **published IDs must never be reassigned or regenerated by reordering**. Future inserted lessons need explicitly retained IDs and, when necessary, a curriculum-version migration. Profile edits do not change IDs or fixed lesson answers.

Every lesson has an objective, preceding lesson dependency, new items, previously introduced review items, short explanation, supported example, estimated duration, and representative practice specifications with explicit answers/hints/feedback. All lessons and exercises have `status: 'planned'`. The schema records their implementation phase. These specifications are curriculum planning data, not a runnable assessment engine; Phase 2 must expand them into complete short lessons with authored distractors, matching sets, composition rules and independently verified answers. No runtime grading exists yet.

Vowels and consonants are distinct item categories. Syllables, vocabulary and phrases each retain their own IDs. Phrases identify conversational polite, formal polite or casual speech. Audio records its Korean text, language, presentation mode and relevant limitations. Listening transcripts are separate from question prompts.

The first lesson introduces just ㅏ, ㅣ and silent initial ㅇ. Larger vowel and tense-consonant sets have been split into small lessons. Keyboard orientation is in `u2-l8` before any independent typing task. 받침 appears in Unit 4. Similar modern vowel sounds are not presented as unambiguous audio-only spelling distinctions.

## Persistence and future review

`ProgressRepository` separates load/save from React. The local adapter accesses only `nay-tutor.progress.v1`. State includes schema/curriculum versions, configured family names and confirmation status, completed lesson IDs, per-item mastery, reading preference, last page/preview, and an ISO update time. A future account adapter can implement the same contract without importing Hangeul data.

Mastery records are defined, but not updated in Phase 1: item category, correct/incorrect attempts, hint use, recent outcomes, current level, last practice and next review. Scheduling and lesson completion are reserved for the requested phases. Merely opening a preview, hearing a reference sample or checking a name spelling cannot award mastery or completion.

Malformed or unsupported stored data falls back to a fresh in-memory session and a warning. The old value is preserved until a deliberate navigation/settings change causes a save. Failed writes warn that data may not persist. No reset/migration/export flow is claimed.

## Audio and privacy

Playback requires a tap and a discovered Korean system/browser voice. It never substitutes an English voice. Consonants are represented by full syllables such as 가 or 나; no isolated consonant-phoneme reliability is assumed. No autoplay, speed selector, microphone, pronunciation grading, accounts, analytics or paid API exists. Speech engine/network behavior depends on the installed browser/OS voice.

The source service’s unit tests verify lifecycle and error handling; a deterministic browser mock verifies the unavailable-voice message. This is not evidence that speech is audible or accurate on a physical iPhone. Reference audio does not create mastery evidence.
